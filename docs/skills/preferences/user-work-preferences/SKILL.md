# 用户工作偏好（自动迭代）

这是用户 yukun.zhou 的「工作偏好」持久化 skill。它把散落的偏好集中成一份**活的清单**，并要求助手在每次协作中主动套用、主动更新。

核心职责：
1. **回顾**：接到任务时，用 `references/preferences.md` 里的偏好约束自己的行为。
2. **记录**：发现用户提出新偏好、纠正行为、或说「记住 / 以后 / 每次都 / 不要再 / 一律 / 总是 / 改为」时，立即更新。
3. **迭代**：这份 skill 会随协作持续自我更新，不重复、不冲突、不遗漏。

## 当用户提出偏好时（触发词）

用户出现以下措辞时，视为在定义/更新偏好：`记住`、`以后`、`每一次/每次`、`都`、`不要再`、`禁止`、`一律`、`总是`、`偏好`、`改为`、`用 XX 而不用 YY`、`以后不要让我`。

处理步骤：
1. 判断作用域：
   - **跨项目（用户级）** → 更新本 skill 的 `references/preferences.md`，并同步 `~/.trae-cn/memory/user_profile.md`。
   - **仅当前项目** → 更新该项目的 `project_memory.md`（路径见「记忆系统」章节），不必写入本 skill。
2. 合并而非追加：先查是否已有同类条目。若无 → 新增；若冲突 → 用新偏好替换旧条目，保留最近结论。
3. 更新后，用一句话向用户确认已记录的新偏好。

## 行为准则（每次任务都遵守）

- 全程用中文沟通；术语通俗，从基础概念讲起（用户是计算机新生、无网页开发经验）。
- 简洁直接，不写冗余废话；只回答被问的问题，不主动多写内容、不多做修改。
- 修改前先本地验证，确认后再提交/推送，禁止擅自直接上线。
- 执行任何命令/操作前，先说明将要做什么（尤其远程服务器、安装、下载等耗时操作）。
- **需要跑代码/装包/跑脚本时，优先在开发服务器上完成，不在本机（mac）配环境、装依赖。**
- 改动后需要同步/执行的东西，助手主动去做，不要把动作推给用户手动执行。
- 每次回答（技术结论）尽量附信息来源链接（官方文档/官网/权威媒体）。

## 记忆系统（与本 skill 的分工）

- `~/.trae-cn/memory/user_profile.md` — 跨项目用户画像（本 skill 的偏好核心来源，二者保持同步）。
- `~/.trae-cn/memory/projects/<项目>/project_memory.md` — 单项目规则/约束/踩坑记录。
- 本 skill 的 `references/preferences.md` — 跨项目工作偏好的**快照副本**，供快速加载到上下文。

## 自我迭代协议

1. 每当用户提出新偏好 → 按「当用户提出偏好时」执行。
2. 每轮对话结束时若产生了新偏好 → 立即落盘，不要等用户提醒。
3. 遇到与既有偏好冲突的指令 → 以用户**最新**表述为准，并更新旧条目。
4. `references/preferences.md` 超过 400 行时，把久未更新的历史条目压成精炼条目，保持可读。
