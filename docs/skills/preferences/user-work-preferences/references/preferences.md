## 流程任务与日志
- 流程/多步任务（≥3 步、可能中断或等确认）要维护一份可监控的过程文档（progress-doc 模式）：开工先写计划，每步 `pending → in_progress → done` 即时回填「结果 + 证据 + 下一步」，失败如实记 `blocked`；让用户随时看清进度，而不是等最终总结
- 证据优先：写完整命令 + 关键输出 + 产物绝对路径；禁止用「已完成 / 已修复 / 成功」这类模糊词，必须可复现
- 长期项目的每次改动回填维护日志（maintenance-log 模式：日期 + 改了什么 + 为什么 + 怎么验证 + 遗留），与代码同仓库一起提交
- 状态词固定五种 `pending / in_progress / done / blocked / skipped`，不造「进行中 / 基本完成」这类模糊词，便于 grep 定位卡点
